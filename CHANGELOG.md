# Changelog

## Unreleased

- W-B2: refinements of the workbench panels after the design review. `Synapbiz.Brain.Workbench`: sentences join lists with a final joiner and no comma before it (` y ` / ` and `; ` o ` / ` or ` for `In`; ` ni ` / ` or ` for `NotIn`), and the set and emptiness templates read more plainly ("es", "no es", "tiene valor", "no tiene valor"), so the templates are no longer a verbatim copy of the source generator. `Synapbiz.Brain.Workbench.Blazor`: new `WorkbenchRule.HeadlineFields` (the only API change); a review control in each row of the test table; no repeated value in the why-sentence and "Row by row"; any-value conditions left out (a row with none shows "Always met."); labelled boolean and number values; a money input with a currency select (USD plus the currencies of the rule) and a language on the date input; rows that do not apply folded only above six rows; a fix or a question needs its note, and the export is held until every such note is written. Six new string keys (199 in all) and a reworded `hint.money`; 330 headless and 297 bUnit tests; the demo pictures were captured again, with two new ones.
- W-B: `Synapbiz.Brain.Workbench.Blazor`, the rule workbench panels as a Razor class library whose only public component is `RuleWorkbench`: rule list, Read, Simulate (with a per-row explanation and the engine refusal in words), Test cases (with a form to propose a case), Review and export of `brain.rule-review@1` files through a host callback. The host supplies rules, locale, a `WorkbenchSession` it owns, a clock and an optional export callback; fixed strings come from `WorkbenchStrings` (Spanish and English, 193 keys, overridable except that the four markings are never emptied); the stylesheet reads only `--wb-*` tokens. Also `RuleLabels.ValueFormatter` in `Synapbiz.Brain.Workbench`. 201 bUnit tests, 4 coupling tests and the purity scan extended to the new assembly; a demo host in `samples/` with a Playwright screenshot script. Docs: `docs/reference/rule-workbench-panels.md`. The solution now packs five packages.
- W-A: `Synapbiz.Brain.Workbench`, a headless rule workbench for `brain.rule@1`. Plain-language rule views with one sentence per row in English and Spanish (templates of the source repository's sentence generator, labels from `meta.display`), fact input parsing with typed error codes, simulation on the real engine with a per-row explanation, test runs with extra cases, revision diff and behaviour comparison, and the `brain.rule-review@1` review document. 299 tests on synthetic fixtures (`tests/fixtures/workbench`), purity scan and reference freeze extended to the new library. Docs: `docs/reference/rule-workbench.md`. The solution now packs four packages.
- W1-A: `Synapbiz.Brain.Process`. The `brain.process@1` document (schema, loader with 20 static diagnostics in English and Spanish), the pure process interpreter (`BrainProcess.Start` and `Advance`: variables, read, action, ai, decide, humanTask, wait, timer, loop, subprocess and end steps, retries, events, cancel, resume, suspension, limits, deterministic identifiers), the serializable `ProcessState`, requests and history with decision provenance, and an embedded scenario runner with a virtual clock. Process conformance cases, interpreter, state, determinism and reference-process tests, the purity scan and a coupling test extended to the new library, and the reference page `docs/reference/brain-process-v1.md`. The solution now packs five packages. Repair pass: cycles are checked without loop body edges, ai schemas must be self-contained (`process.ai.schema_invalid`), duplicate JSON member names are rejected everywhere, integer bounds are exact, instants are UTC, and suspension cancels outstanding work.
- W1-B: `Synapbiz.Brain.Host.Postgres`, the durable PostgreSQL host of `brain.process@1` instances. Instance, history, timer, wait, task, effect, event and inbox tables created by an idempotent migrator; one transaction shape (instance row locked first, work item re-validated under the lock) for every change; a pump (expired leases, inbox, due timers, effects) and a hosted worker, safe with several workers; `AtLeastOnce` effects re-delivered with the same idempotency key and `AtMostOnce` effects turned into an `Unknown` outcome after a crash; event de-duplication and routing by wait and correlation; human tasks, child processes, cancel and resume; payloads through an `IPayloadProtector`; no protected value in logs. Integration tests on a real PostgreSQL (including the five outreach scenario paths and two concurrency tests), architecture tests freezing the reference set and confining `Npgsql` to the store and the migrator. Docs: `docs/reference/process-host-postgres.md`. The solution now packs seven packages.

## 0.1.0 (2026-11-22)

- Release workflow publishing to the private GitHub Packages feed on a version tag, a manual live-parity workflow, and the consumer guide (`docs/consuming.md`).
- B0 PR 1: `brain-engine`. The Decision Engine cores move into this repository as `Synapbiz.Brain.Contracts` (28 files, `BrainException`, `ContentHash`) and `Synapbiz.Brain.Engine` (14 files), with the engine unit tests, architecture guards (BCL-only references, no package references, engine purity), the source drift guard and the live and baseline behaviour parity proofs, and CI.
- B0 PR 2: `brain-spec` for rules. `Synapbiz.Brain.Spec` reads module contracts, loads and validates `brain.rule@1` documents against them with the source repository's codes, paths and messages, projects them to a decision table and golden cases, and runs them on the engine with the document version on the trace. 77 rule conformance cases, a purity scan extended to constructors and type initializers and to the new library, a second drift-guard section for 7 data files, and the `spec/` parity scenarios (310 entries: the 77 rule cases and 38 structure documents; the 364 earlier entries are unchanged). Docs: the rule reference and the interim-shape migration guide. The solution now packs three packages.
